# 多分支画布性能实现与验证

日期：2026-10-22。工作区：`awefork2`。

已完成原方案第一、二、四阶段：末轮判断、消息更新与请求调度、首次加载。第三阶段的组件拆分和视口裁剪暂缓。当前 530 卡片普通场景中位数已达到约 16 ms 的参考目标；完整窗口压力场景仍有长尾，不能据此宣称 60 FPS。

## 实现

- 每会话用 Vue computed 缓存最后一条 user 的 id。消息重载、乐观发送和删除通过响应式依赖使缓存失效；相机移动不扫描历史。删除按钮判断改为检查首条消息，保留原有删除语义。
- 按会话键发布消息；完整消息状态相同则保留数组引用。比较包含 thinking、工具、模型、附件、完成原因、token、错误及压缩标记。相同流式尾文跳过发布。
- 以 backend + sessionId 串行合并读取；完成及显式刷新安排一次后续新读取。发送、删除使旧快照失效；新发送立即终止旧 watchdog，避免旧轮询结束新运行。
- 独立会话的变化消息在动画帧集中发布，并提供 32 ms 定时器兜底；读取完成前保证已处理发布。迟到流式帧不能重新点亮已完成运行。
- 优先加载选中分支及祖先，其余分支最多四个画布读取并发。旧工作区尚未开始的任务取消；在途结果可补缓存，不得清除新工作区的加载状态。
- 区分选中分支就绪和整批加载完成。后续卡片高度变化时保持请求定位的节点居中；手动拖动、缩放或全图适配后停止跟随。

主要代码：`src/renderer/src/state.ts`、`src/renderer/src/message-loader.ts`、`src/renderer/src/components/session-canvas.vue`。基准脚本为 `scripts/canvas-benchmark.mjs`。

## 测量方法

macOS arm64、Apple M4、Electron 44.2.0、Vue 3.5.42、Node 22.22.0，1440 × 900 独立窗口。使用生产编译的真实组件和样式、内存合成会话，不连接真实 Agent。基准关闭后台节流，并使用独立临时用户目录。

主线 30 轮，每分支继承主线后新增 5 轮。普通场景每轮一条 user、一条 assistant；每条回复约 250 字符、两个工具名。每项先预热 5 次，再采样 30 次。中位数取排序后索引 15，P95 取索引 28。普通场景视口内卡片为 3，完整窗口压力场景为 6。

基线通过 `--source-ref 0728ba9` 读取 Git 中的源码，不修改工作区。它与交接文档基线 `77292b2` 的生产源码相同，仅 `.gitignore` 不同。改后档案记录了最终源码 SHA-256，交付前已与工作区文件核对。

记录事件或发布开始至 Vue nextTick 的耗时，以及到下一个 rAF 回调的耗时。后者位于绘制之前，两者都不能换算成真实 FPS 或输入到绘制的延迟。计数插桩只进入临时编译副本。各次测量串行运行。

## 完整窗口压力场景

包含侧栏与对话面板，100 条分支、530 卡片，每轮 20 条 assistant 消息，开启逐轮删除。流式发布通过 publishParts 更新选中分支的文本和对话面板。[原始数据](2026-10-22/full-stress-after.json)。

| 指标 | 中位数 ms | P95 ms | 最大 ms |
| --- | ---: | ---: | ---: |
| 拖动 | 8.8 | 21.1 | 24.9 |
| 缩放 | 8.3 | 11.0 | 12.2 |
| 流式发布 | 9.2 | 9.9 | 10.2 |

这是改后压力测量，没有同配置的原始基线。拖动 P95 超过 16 ms，仍有长尾；本次交付保留该结果，不以重复测量中的更低样本替代。

## 冷加载与定位

100 条分支；模拟选中会话 15 ms、祖先 30 ms、普通分支 40 ms、一个慢兄弟分支 400 ms 的响应延迟。这些是调度模拟，不代表真实后端速度。[改前](2026-10-22/cold-before.json)、[改后](2026-10-22/cold-after.json)。

| 指标 | 改前 | 改后 |
| --- | ---: | ---: |
| DOM 中首次出现选中分支文本 ms | 92.3 | 122.0 |
| 选中卡片首次进入视口 ms | 测量期间未出现 | 122.1 |
| 全部请求返回 ms | 16478.4 | 1713.1 |
| 最大并发请求 | 100 | 4 |
| 整图重建次数 | 171 | 58 |
| 全部加载后选中卡片可见 | 否 | 是 |

图重建次数包含卡片高度反馈，受响应和帧时序影响。文本进入 DOM 不等于已进入视口。

[加载中手动拖动](2026-10-22/cold-pan-after.json)后，后续加载保持相机 transform 不变（panPreserved=true）。该场景最终选中卡片可以离开视口，视口控制权已交给用户。

## 限制与后续

真实后端、多分支同时输出、完整绘制、输入延迟和长期内存占用未测。画布内消息真正变化时仍会重建整图；卡片和小地图仍由原组件遍历。更大规模或真实场景再次出现卡顿时，使用本基准评估组件隔离与裁剪，并先处理未测量卡片高度和视口锚定规则。
