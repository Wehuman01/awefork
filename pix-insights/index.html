分支导出为独立会话

来源 9efa821 / 8b277a6 / b3ecde9（v0.0.18）

把当前查看的分支尖端或任意节点导出成一份纯 opencode 会话——可分享、可在任何地方单独继续。 与 awefork「零锁定、纯原生会话」的身份完美契合。已确认 awefork-api.ts 目前没有对应端点，需新增 IPC。

契合产品身份新增 IPC + 写入 注意 off-path 引用
导出流程
1选中节点卡片右键 / pane 菜单
→
2导出为独立会话仅该分支路径上的 turns
→
3纯 opencode 会话TUI 可直接打开
→
4分享 / 继续跨机器、跨工具
⚠ PiX 的教训（b3ecde9）：turn 引用了不在此路径上的内容时导出会失败 —— 导出前做引用预检，失败时给出明确文案，而不是静默坏文件。

稳定性启示

对应 awefork 最近在修的方向（opencode 端口发现 / 目录归组）。PiX 的 registry 重构是现成参考图纸。

路径规范化只做一次

每次 listing 只做一次 realpath 规范化；配套 fixture 处理 macOS /var vs /private/var。awefork 按目录归组会话，同一经典陷阱。

落点 dirs-store.ts · 1ef0da8 / 9ed3c39
运行时中途关闭要设防

PiX 给 stop 快照加了「runtime 在请求中途关闭」守卫。awefork 的流式回复与快照同样暴露在 opencode 崩溃风险下。

落点 state.ts · sse.ts · c17c131
图片附件显式限额

attachments.ts 目前图片 verbatim 发送、无上限，渲染层还要整段 base64。PiX 定为每张 20MB / 总 40MB——要有上限，且定在用户不抱怨的水平。

落点 attachments.ts · 4073acf / 5e06a50
CI 在 PR 上也跑 verify

PiX 把验证矩阵扩到 pull_request 触发。awefork 已有 npm run verify（awecontrib 体系），确认 PR 也触发即可。
